# Benchmarking an ancestry / segmentation caller against the simulation

This simulation produces **ground-truth introgression segments** for 100 (or
1,400) BC2S3 NILs, so you can score *any* ancestry-calling / genotype-segmentation
tool — not just RTIGER — against a known answer. This doc explains the common
scoring schema and the **input-adapter layer** you write to plug your tool in,
using the two real normalizations in `R/06_score_rtiger.R` as the worked example.

## What the benchmark gives you

Under `results/rtiger_benchmark/` (generated by `make_rtiger_benchmark.R`):

| file | purpose |
|---|---|
| `counts/sim_NNNN.tsv` | per-sample allele counts (RTIGER 6-col format: `Chr Pos RefBase RefCount AltBase AltCount`; missing = `0/0`). Feed these to your tool. |
| `expDesign.csv`, `seqlengths.csv` | sample→file table and chromosome lengths (B73 NAM v5 bp). |
| `truth_segments.csv` | **ground truth**: `name, chr, start_bp, end_bp, state, n_markers`. |
| `truth_markers.rds` | per-marker true dosage (`name, chr, bp, dosage`) for marker-level scoring. |

If your tool wants a different input format (VCF, allele-ratio matrix, etc.),
convert from `counts/` — the genotype information (REF/ALT read counts per marker)
is all there.

## The common scoring schema

The scorer compares everything as a tidy **segment table** with exactly these
columns:

```
name      character   sample id; MUST equal the truth's `name` (sim_0001 …)
chr       integer     1..10        (NOT "chr1"; NOT a factor)
start_bp  integer     1-based, B73 NAM v5
end_bp    integer
state     integer     0 | 1 | 2
```

**State encoding** (donor = teosinte = ALT; recurrent = B73 = REF):

| state | meaning | RTIGER `CompleteBlock` | RTIGER `@Viterbi` |
|---|---|---|---|
| 0 | homozygous recurrent (REF/B73) | `AA` | `pat` |
| 1 | heterozygous | `AB` | `het` |
| 2 | homozygous donor (ALT/teosinte) | `BB` | `mat` |

To benchmark your tool you write **one adapter function** that turns its output
into this table. Everything downstream (`score_markers`, `score_segments`,
`score_cos` in `R/06_score_rtiger.R`) is tool-agnostic.

## The two gotchas every adapter must handle (worked example: RTIGER)

These are the normalizations in `R/06_score_rtiger.R`. Both produced a silent
failure mode worth flagging: **the join still "runs" but every overlap is zero**
(0 TP, 100% "uncovered", `NaN` precision/recall) because the *labels* don't
match even though the coordinates are fine. If you see all-zero overlaps, suspect
a label mismatch, not your tool.

### 1. Chromosome labels — normalize to integer `1..10`

RTIGER emits `chr1 … chr10` (string) in its BED/GRanges output; the truth uses
integer `1..10`. The reader strips the prefix and coerces:

```r
chr = as.integer(stringr::str_remove(raw_chr, "(?i)^chr"))
```

Adapt this to whatever your tool emits (`Chr01`, `S1`, `1`, a factor, …). The
rule: **match the truth's chr type and values exactly** (integer 1..10). A
type-only cast (`as.character`) is *not* enough — `"chr1"` ≠ `"1"`.

### 2. Sample names — map the tool's internal ids back to the originals

RTIGER renames samples to `Sample_1 … Sample_N` internally (in `@Viterbi` and
`info$sample_names`) and stores the original name in
`info$expDesign$OName`. If you score the `Sample_N` ids against truth keyed on
`sim_NNNN`, the `name` join misses entirely. The reader maps back:

```r
ed <- res@info$expDesign
name_map <- setNames(as.character(ed$OName), as.character(ed$name))
out_name <- name_map[ internal_sample_id ]
```

(RTIGER's on-disk BED filenames *do* carry the original name, so the file-based
reader doesn't need this — only the object/`@Viterbi` reader does. Tools differ:
check whether yours renames, reorders, or drops samples, and re-key to the
truth's `name`.)

## Writing an adapter for your tool

1. Run your tool on `results/rtiger_benchmark/counts/` (or a format you convert
   from it).
2. Write `read_<tool>_segments(path) -> tibble(name, chr, start_bp, end_bp, state)`:
   - parse your tool's segment/state output,
   - **normalize `chr`** to integer 1..10 (gotcha 1),
   - **re-key `name`** to the truth's sample ids (gotcha 2),
   - map your tool's state labels to `0/1/2` (donor-dosage convention above).
3. Score — reuse the tool-agnostic functions in `R/06_score_rtiger.R`:

```r
purrr::walk(fs::dir_ls("R", glob = "*.R"), source)
called <- read_<tool>_segments("your_tool_output/")
truth_seg     <- readr::read_csv("results/rtiger_benchmark/truth_segments.csv")
truth_markers <- readRDS("results/rtiger_benchmark/truth_markers.rds")

# marker-level confusion / accuracy
score_markers(assign_called_state(called, truth_markers))
# segment precision / recall / FDR / boundary error per state class
score_segments(called, truth_seg, target = 2L,        label = "homozygous_donor")
score_segments(called, truth_seg, target = c(1L, 2L), label = "donor_present")
# crossover-count recovery
score_cos(called, truth_seg)
```

Or drop your reader into `score_rtiger.R`'s `read_rtiger_segments()` dispatch and
run it end-to-end.

## Metrics produced

- **Marker-level**: confusion matrix (true×called over 0/1/2), per-state
  recall/precision, overall accuracy, uncovered fraction — resolution-independent.
- **Segment-level**: precision / recall / F1 / FDR by reciprocal overlap
  (default ≥ 0.5), for homozygous-donor, donor-present, and heterozygous classes,
  plus median boundary error (kb).
- **Crossovers**: true vs called detectable CO counts per sample (bias, RMSE).

See [08-scoring.md](08-scoring.md) for the metric definitions and a self-test
(`score_rtiger.R --demo`), and [09-rigidity-selection.md](09-rigidity-selection.md)
for the SNP50K coverage floor that bounds achievable recall.
